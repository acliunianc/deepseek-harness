# 容量地图（影刀计划）

DSH Web 客户端里的「容量地图」主面板：读取影刀控制台的计划接口，把每个计划按执行时长展开成时间轴，显示任务重叠、机器人占用与容量缺口。

它不是独立应用：面板挂在 `@deepseek-ai/dsh-client-ui-schedule` 的浏览器半边，随 Web 客户端一起加载；数据由浏览器直接请求 `https://api.yingdao.com`（该接口按 `Origin` 放行，已在 `127.0.0.1:3080` 验证）。

## 使用

1. 侧边栏点「容量地图」。
2. 首次打开显示演示数据（35 个计划，含 08:00 早高峰超载）。
3. 点「连接影刀」，从控制台 `F12 → Network → api.yingdao.com` 请求里复制：
   - `authorization`（去掉 `Bearer `）→ Authorization Token
   - `x-credential`（可选，401/403 时再填）
4. Token 每天更新；可勾选「在这台电脑记住」，否则只存 `sessionStorage`。
5. 加载成功后会写入本地缓存；以后打开面板直接显示缓存，点「刷新」才重新拉取。

## 表格筛选与排序

筛选分成两组，可以叠加：

- **类型**（右侧带数量）：
  - **计划执行**：cron / 每天 / 每周 / 每小时这类重复计划；
  - **定时执行**：一次性 `timer`（例如“仅一次 · 10/23 14:00”）；
  - **手动执行**：`manual`；
  - **已停用**：`enabled=false`。
- **范围**：全部、本区间有执行、参与排期、超载相关、条件任务、每小时触发、待校准。
  - 「本区间有执行」只保留当前 7/14 天里真的触发过（含心跳）的计划；
  - 「参与排期」保留所有启用计划，即使它在本区间没有触发。

**排序**：点表头（任务、机器人组、执行时长、实例、总占用、状态）切换排序列，再点一次切换升/降序；箭头显示当前列与方向。搜索、类型、范围、排序互相叠加，选择会保存在本机。

## 数据刷新

计划一般不会变，所以面板**不会自动请求接口**：

- 连接成功或手动刷新的结果会缓存到本机浏览器；之后打开面板直接读缓存（标签显示琥珀色「缓存数据」+ 上次同步时间）。
- 只有点右上角 **「刷新」** 才会重新请求影刀；刷新失败保留原有数据并提示原因。
- 缓存与 Token 都只在本机浏览器里，不会上传；换电脑需要重新连接。
- 头部的「缓存数据 / 影刀实时 / 演示数据」标签说明当前数据来源。

## 执行时长：从执行记录估算

计划接口不含单次耗时，所以时长来自影刀控制台的**执行记录**接口 `POST /api/dispatch/v3/scene/inst/page`（`runTime` 单位为秒，`sourceUuid` 是计划 UUID）。

- 任务表右上角 **「从执行记录估算」**：对每个计划读取最近 30 天、最近 40 次「完成」记录，自动算出**中位数与平均值**并填入样本。只更新本机数据，不修改影刀计划。
- 打开任务行的「执行时长」，可以在 **中位数 / 平均值 / 手动指定** 三种口径间切换；弹层同时显示中位数、平均值和样本数。
- 条件任务同步时会自动忽略不足 30 秒的心跳记录；只点一次按钮，之后仍按「手动刷新」的节奏使用，不会自动请求。
- 样本支持直接编辑（`12`、`3分12秒`、`00:03:12`），也支持「批量录入时长」。

## 条件任务（每小时巡检、到点才执行）

影刀不能设置“每 25 小时执行”，常见做法是每小时触发一次，任务里查数据库判断是否到点：没到点就立刻结束，到点才真正执行。这种任务不能用一个固定时长表示。

在任务行点「执行时长」，勾选 **条件任务**：

- **检查耗时**：每次触发只占几秒（默认 5 秒）。
- **实跑周期**：例如 25 小时。
- **最近一次实际执行时间**：按它和周期向前后推算；到点后的第一次触发执行完整任务。例如每小时触发 + 25 小时周期，实跑会落在 08:00、09:00、10:00…（每天顺延一小时）。
- **实跑耗时样本**：只填真正执行时的耗时；不足 30 秒的样本会按心跳检查忽略，中位数不会被“秒退”记录拉低。

计算上：

- 心跳检查按秒计入任务表与机器人占用，但**不参与并发峰值、热力图与超载判断**（否则每个整点都会出现一个假峰值）。
- 实跑实例正常参与并发、超载与机器人分配；泳道里用较矮的细条表示心跳检查。
- 任务表显示「条件任务」状态，并注明“每 N 小时实跑 · 检查 X 秒”；筛选栏可只看条件任务。

## 计算口径

- **执行时长**：优先取执行记录样本的中位数或平均值（可在任务行切换），其次手动固定值，都没有时按工具栏的「未校准任务按 N 分钟估算」。
- **并发**：按计划触发时刻展开成区间，事件扫描得到并发段；相邻超载段合并为「超载时段」。
- **机器人分配**：贪心模拟——优先用刚好空闲的机器人，否则排最早空出来的那台。它是风险参考，不代表影刀真实调度。
- **容量**：默认 3 台，可改；所有机器人视为共享容量池（不区分机器人组配额）。
- 时区固定 `Asia/Shanghai (+08:00)`；cron 为 5 段；「每周」类型按 `1=周一 … 7=周日` 解释。

## 结构

```
capacity/
├─ CapacityPage.tsx    Shadow DOM 宿主 + CSS 注入
├─ CapacityIcon.tsx    侧边栏图标
├─ shell.ts            页面骨架
├─ app.ts              页面交互与渲染（迁移自独立版，DOM 视图）
├─ core.ts             cron、并发、机器人分配（纯函数）
├─ demo.ts             演示数据
└─ capacity.css        页面样式（作用域在 Shadow DOM 内）
```

注册点：`src/client/index.ts` 同时向 `main`（key `capacity`）与 `sidebar.panellist`（id `capacity`）注册；侧边栏文案在 `task-manager-locales.ts` 的 `capacity.panel`。

## 说明

- 页面在 Shadow DOM 内渲染，DSH 主题与全局样式不会影响图表排版，页面样式也不会外泄。
- `app.ts` 是从独立版迁移的纯 DOM 视图，带有 `@ts-nocheck`；纯计算逻辑在 `core.ts` 中保持严格类型。
- 界面文案为中文硬编码（内部工具），未接入 DSH 的 locale 字典；侧边栏标签使用了字典。
